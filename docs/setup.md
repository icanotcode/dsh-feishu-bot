# 飞书接入指南

[返回项目首页](../README.md) · [故障排查](troubleshooting.md)

本指南适用于当前版本的 DeepSeek Harness **Web profile**，接入飞书企业自建应用。先按首页完成源码安装，再配置应用与消息接收方式。配置完成的验收标准是：发送一条真实飞书文本消息，Harness 生成会话，机器人回复最终文本。

运行环境需 Node.js **22.13 或更高版本**，历史数据库使用内置 `node:sqlite`。首页截图展示隔离测试环境中的多机器人配置；姓名确认与每日上下文切换设置位于表单下方。

## 1. 准备应用和 Harness

1. 打开 [飞书开发者后台](https://open.feishu.cn/app)，创建或选择企业自建应用，在应用能力中添加机器人。
2. 在「凭证与基础信息」取得 **App ID** 和 **App Secret**。这里需要应用凭据，不是群自定义机器人的发送 Webhook 地址。
3. 启动 Harness，先在网页中完成模型配置，确认普通会话能够正常得到答复。
4. 打开 **设置 → 插件 → Plugin list**，搜索 `feishu`，确认 **Global plugins（全局插件）** 中的 `feishu-bot` 已启用。展开卡片即可直接配置；插件不再提供单独的飞书标签页或侧栏入口。
5. 在顶部选择默认机器人，或点击 **添加机器人** 填写名称并通过 **搜索项目** 选择独立项目目录。已有机器人的目录在 **任务处理** 中选择。随后填写所选机器人的应用凭据和 Agent 预设，再按下文选择接收方式。每位用户仅使用项目目录下自己的 `.feishu-users/<身份哈希>/`，不会取得项目已有文件的访问权限。

安装脚本会把源码目录链接到 `web` profile，安装后请保留该目录。如果使用自定义 `DSH_HOME`，安装和启动应使用同一个值，才能读取同一份插件与配置。

### 多个项目与飞书应用

一个 Harness 只需安装一次插件、启动一个服务器，即可添加多个机器人。每个机器人对应一个项目，分别保存 App ID / App Secret、Webhook 验证凭据、接收方式和工作目录。不同机器人不能使用同一个 App ID 或重复项目目录；目录仍是各自用户子目录的根路径，不会把根目录中的文件自动共享给所有用户。

在 **任务处理** 或 **添加机器人** 中点击 **搜索项目**，展开列表后输入项目名称或路径即可实时过滤。列表显示 Harness 已添加的项目及机器人已绑定目录，不扫描磁盘；选择结果后，保存配置或创建机器人才能生效。被其他机器人占用、已删除或无法访问的目录不可选。若找不到目标目录，先在 Harness 中添加该项目，再刷新列表。各机器人的项目和用户数据继续隔离。

App ID 首次绑定后不可替换，尝试更换会返回 `409`。如需接入另一个飞书应用，请新增机器人，让原应用的历史继续保留；同一应用的 App Secret 等凭据可以更新，忙碌时须等待当前任务完成后再保存。

顶部 **当前机器人** 选择器切换配置，**重命名**修改显示名称，启用开关控制是否接收消息和执行任务。停用不删除凭据、会话或历史；任务运行中会拒绝停用，等任务完成后再试。切换时如有未保存配置，可取消切换或确认放弃，不会把草稿保存到另一个机器人。

每个机器人的用户资料、姓名确认、数据库、当前会话和附件分开；同一用户在不同机器人中可各有一个当前会话。升级前的应用自动作为默认机器人保留原凭据、回调路径、工作目录和历史，不需要重新注册用户。

所有 Webhook 机器人共享 Harness 端口和 ngrok / Cloudflare 公网根地址，隧道只在 **默认机器人（共享隧道设置）** 中编辑、启动和守护。默认机器人可以使用长连接；只要还有其他启用的 Webhook 机器人，这里仍显示共享隧道控件。其他机器人的 Webhook 面板只显示共享状态及自己的完整回调地址。

**各飞书应用必须填写各自回调 URL。** 默认地址为 `/webhook/feishu`，新增机器人自动分配稳定子路径，不受重命名影响。选择对应机器人并复制页面地址；不要把默认机器人的 URL 填给所有应用。更换公网域名或重启临时隧道换地址后，逐一更新所有 Webhook 应用的请求地址。

如果已有 ngrok Traffic Policy、Cloudflare Access 或反向代理规则只放行 `POST /webhook/feishu`，还需逐一允许新增机器人的 POST 回调路径，否则新应用的验证请求会被拦截。只为各机器人的回调添加例外，管理页面与其他接口继续保留访问保护；插件不会改写现有入口策略。

## 2. 选择事件接收方式

| 项目 | 开发者服务器（Webhook） | 长连接 |
| --- | --- | --- |
| 插件选项 | 将事件发送至开发者服务器（Webhook） | 使用长连接接收事件 |
| 事件如何到达 | 飞书向公网 HTTPS 地址发送 POST 请求 | Harness 使用飞书 SDK 建立连接接收事件 |
| App ID / App Secret | 需要，用于应用认证和回复 | 需要，用于连接、应用认证和回复 |
| 公网域名 / 隧道 | 需要可达的公网入口 | 不需要，本机需能访问飞书服务 |
| Verification Token / Encrypt Key | 按应用的加密策略配置，见下文 | 不需要 |
| 飞书后台填写请求地址 | 需要完整的 Webhook URL | 不需要 |

两种方式均通过 `im.message.receive_v1` 接收文本、图文和支持的附件，功能范围相同。修改下拉选项后必须点击 **保存配置** 才生效；飞书后台也要选择相同方式。长连接模式下，该机器人的 HTTP Webhook 入口返回 `409`，同一个机器人的两个入口不会同时接收消息；不影响其他机器人选择自己的模式。

### 方式 A：开发者服务器（Webhook）

1. 选择要配置的机器人，再选择 **将事件发送至开发者服务器（Webhook）**。服务器公网接入方式统一在默认机器人下选择 ngrok、Cloudflare Tunnel 或自定义公网地址。
2. 在飞书后台 **事件与回调 → 加密策略** 中取得 Verification Token；如果启用了事件加密，同时取得 Encrypt Key。将这些值填写到插件并先点击 **保存配置**。
3. 将公网 HTTPS 入口转发到 Harness 实际监听端口，默认是本机 `3080`。
4. 在默认机器人的 **公网服务地址** 中填写域名根地址，例如 `https://your-domain.example` 并保存，再切换到目标机器人，复制它显示的 **Webhook 地址**。
5. 飞书后台打开 **事件与回调 → 事件配置**，编辑订阅方式，选择 **将事件发送至开发者服务器**，填写复制的完整地址并保存。
6. 完成下文的事件订阅、权限和应用发布，再测试真实消息。

以默认机器人为例，两处地址的填写方式不同；新增机器人以其面板生成的完整 URL 为准：

| 填写位置 | 示例 |
| --- | --- |
| 插件「公网服务地址」 | `https://your-domain.example` |
| 飞书「请求地址」 | `https://your-domain.example/webhook/feishu` |

插件「公网服务地址」只接受 HTTPS 根地址，不接受路径、查询参数或 URL 中的用户名密码。保存请求地址时，飞书会向该地址发起验证请求，插件读取 `challenge` 并返回同一个值；启用加密时会先解密。此步骤不调用模型，不需要等待 Agent 生成答复。订阅流程可参阅 [飞书：配置事件订阅方式](https://open.feishu.cn/document/server-docs/event-subscription-guide/event-subscription-configure-/request-url-configuration-case)。

#### 使用本机 ngrok

在公网接入方式中选择 **ngrok**。先自行安装并配置 ngrok，在插件源码目录的另一个终端运行：

```bash
npm run start:ngrok -- --url https://YOUR-NGROK-DOMAIN --port 3080
```

`--port` 与 Harness 的实际监听端口保持一致；也可通过 `NGROK_URL` 提供域名。有自己的 traffic policy 时，可追加 `--traffic-policy-file PATH`。策略需要允许飞书的 Webhook 请求到达该路径，不应要求飞书完成浏览器登录；Harness 管理页面仍应保留原有访问保护。

设置页会显示只读的「当前 Harness 监听端口」，并用实际端口生成 ngrok / Cloudflare 启动命令，端口不固定为 `3080`。例如要改为 `4321`，先停止原 Harness 实例，再运行 `npm run start:harness -- --port 4321`，同时把隧道的目标端口改为 `4321`。插件共用 Harness 的 HTTP 服务，没有独立监听端口；仅修改隧道端口或保存插件设置不会移动该服务。

插件会读取本机 `127.0.0.1:4040` 的 ngrok 隧道信息，仅选择指向当前 Harness 端口的 HTTPS 隧道。如果「公网服务地址」留空，可用检测到的隧道生成 Webhook URL。填写了公网服务地址时，以填写值为准。设置页可启动和守护 ngrok，也可继续使用手动启动的外部进程。检测还会匹配已填写的公网域名，避免把另一个隧道误报为可用。

#### 使用 Cloudflare Tunnel

在公网接入方式中选择 **Cloudflare Tunnel**。先按 [Cloudflare 官方安装说明](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/) 安装 `cloudflared`，确保终端能找到该命令。

临时验证可以使用 Quick Tunnel。在插件源码目录的另一个终端运行：

```bash
npm run start:cloudflare -- --port 3080
```

将启动日志中的 `https://…trycloudflare.com` 根地址填写到插件 **公网服务地址** 并保存，再将该根地址加 `/webhook/feishu` 填入飞书后台。`--port` 必须等于 Harness 实际监听端口；Quick Tunnel 退出后域名不能继续使用，下次启动获得新地址时，应同步更新插件与飞书后台。

长期使用建议创建命名隧道，并把自己的域名路由到 Harness。完成 Cloudflare 账户、域名、隧道凭据和配置文件准备后，可运行现有命名隧道：

```bash
npm run start:cloudflare -- --name YOUR-TUNNEL --config /path/to/config.yml
```

`--name` 与 `--port` 不能同时使用；命名隧道的本地目标由配置文件中的 `ingress` 决定，例如 `http://127.0.0.1:3080`。插件脚本只启动现有隧道，不负责创建账户、申请域名、创建隧道或修改 DNS。部署细节见 [Cloudflare 本地管理隧道指南](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/create-local-tunnel/)。

外部 Cloudflare 隧道和固定域名模式需填写公网服务地址；插件托管的 Quick Tunnel 可从启动输出识别本次 URL，不读取或回退到 ngrok。**保存地址只表示完成配置，不代表 Cloudflare 已运行或公网已连通。** 如有 Cloudflare Access 或其他入口策略，飞书 POST 回调必须能够到达各机器人面板显示的路径，包括新增机器人的子路径；管理页面的访问保护应继续保留。

#### 隧道守护与一键启动

在公网接入设置中填写对应程序参数，保存后点击 **启动当前端口的隧道**。未保存的隧道草稿会禁用启动按钮，避免启动错误的接入商或地址。程序需预先安装；留空程序路径时从 PATH 查找，也可填写带空格的本机绝对路径，Windows 选择原生 `.exe`，不要填写整条命令或 `.cmd`/`.bat`/`.ps1`。

| 设置 | 行为 |
| --- | --- |
| 隧道守护 | 默认关闭；开启并保存后启动缺失隧道，退出或持续无法连接时退避重试，间隔上限 60 秒 |
| ngrok Traffic Policy 文件 | 显式文件必须可读取；留空探测 `~/.config/ngrok/policy.yaml`，原策略保持不变 |
| ngrok Authtoken | 可选；留空保留已保存凭据，程序也可使用自己的已登录配置；不会回显或加入命令参数 |
| Cloudflare 临时隧道 | 转发至当前 Harness 端口，面板显示生成的 `trycloudflare.com` 地址；变化后重新填写飞书回调 |
| Cloudflare 固定命名隧道 | 填隧道名称/UUID、本地 YAML 配置文件和公网根地址；本地配置需已有 `credentials-file` 及匹配域名的 HTTP ingress |
| 程序路径 | 各平台对应的 ngrok / cloudflared 原生程序绝对路径；留空使用 PATH |

固定命名隧道会生成私有临时配置副本，仅替换匹配公网域名的本机 HTTP 上游端口，保留原规则及原始配置文件。首次需自行创建隧道、凭据和 DNS；仅有 Dashboard tunnel token 的远程管理方式暂不支持。配置文件内相对 `credentials-file` 路径相对于原配置文件目录解析。

关闭守护不关闭现有隧道。点击 **停止托管隧道** 会停止插件拥有的进程并暂停自动重试；点击启动，或将守护关闭保存后重新开启保存，可恢复。切换接入商或关键隧道配置时，会停止不再适用的托管进程；仅将一个机器人切换为长连接，不会停止其他 Webhook 机器人仍需使用的共享隧道。Harness 正常退出时停止自身托管隧道，守护不会在 Harness 退出后继续运行。

检测到已有匹配的 ngrok 隧道时不会重复启动，也不会杀掉外部进程；开启守护后若它消失，可启动插件自己的进程。已有但不匹配端口/域名的 ngrok、或检测超时，会明确提示，避免盲目重复启动。Cloudflare 没有等价的通用外部进程检测：已有外部 Cloudflare 进程请继续在原终端或系统服务中管理，不要重复点击启动。

面板显示启动中、已检测/已连接、等待重试、失败及暂停状态。ngrok 本地 API 反映隧道登记状态；Cloudflare 依据连接日志更新状态，二者都不替代飞书回调验证。公网接入为“自定义”或使用 WebSocket 时无需启动守护隧道。

#### 使用自定义公网地址

已有反向代理或其他公网 HTTPS 入口时，选择 **自定义公网地址**，填写根地址并保存。确保入口将回调路径转发到 Harness 实际端口。此方式同样不会启动代理、自动检测 ngrok 或验证公网连通性。

### 方式 B：长连接

1. 插件填写 App ID 和 App Secret，选择 **使用长连接接收事件**，点击 **保存配置**。
2. 等待状态显示 **当前运行：长连接 · 已连接**；可点击 **刷新连接状态**。
3. 飞书后台打开 **事件与回调 → 事件配置**，选择 **使用长连接接收事件** 并保存。
4. 完成下文的事件订阅、权限和应用发布，再测试真实消息。

长连接由 Harness 进程维持。关闭 Harness 后就无法接收消息；重启后会根据保存的配置重新建立连接。该方式无需填写公网地址，也不需要 ngrok、Cloudflare 或其他隧道；Verification Token / Encrypt Key 同样不需要。

## 3. 订阅事件、配置权限并发布应用

在 **事件与回调 → 事件配置** 中添加 **接收消息 `im.message.receive_v1`**。自动聊天只需要这一项事件，更多事件不会自动增加插件能力。

在「权限管理」中按实际使用场景开通应用身份权限：

| 场景 | 应检查的权限名称 |
| --- | --- |
| 接收用户私聊机器人的消息 | 读取用户发给机器人的单聊消息 |
| 接收群里 @机器人的消息 | 获取群组中用户 @机器人消息 |
| 回复处理结果 | 以应用的身份发消息 |
| 添加/删除敲键盘工作状态表情 | 发送、删除消息表情回复（`im:message.reactions:write_only`） |

飞书可能提供多项可满足同一接口的权限，具体以当前后台提示为准。不要为了接通文本聊天，一次性申请所有文档、日历或通讯录权限。接收条件和回复权限分别见 [飞书：接收消息](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)、[飞书：回复消息](https://open.feishu.cn/document/server-docs/im-v1/message/reply)。

`Typing` 工作状态表情通过主动调用飞书 API 添加和删除，不需要订阅 `im.message.reaction.created_v1` 或 `im.message.reaction.deleted_v1`。权限详情见 [飞书：添加消息表情回复](https://open.feishu.cn/document/server-docs/im-v1/message-reaction/create) 与 [删除消息表情回复](https://open.feishu.cn/document/server-docs/im-v1/message-reaction/delete)。新增权限后必须完成发布/生效流程，不能只在权限管理页面勾选。

完成 **版本管理与发布** 中的创建版本、发布或审批流程，确认应用对测试用户可见。群聊测试前将机器人加入群，并 @机器人发送文本。用户接入范围由飞书后台的应用可用范围控制，请在发布前核对。插件不再维护用户准入白名单，也无需预填用户 `open_id` 和姓名；事件接通后，用户按下文完成姓名确认。姓名确认只是设置称呼，不是身份认证或管理员授权。

**「回调配置」无需为当前聊天功能添加项目。** 插件未处理 `card.action.trigger` 卡片按钮交互。机器人入群/出群、已读/撤回、用户表情回应事件、云文档评论、会议和纪要/妙记等事件也不在当前处理范围内。

### 附件权限

附件需要分别完成“下载用户消息资源”“上传资源”和“回复消息”的权限配置。已能接收文本事件不代表这些 API 都已授权。以下以官方 API 文档当前列出的应用身份权限为准；同一接口可能接受多项权限中的任意一项：

| 用途 | 官方 API 与权限要求 |
| --- | --- |
| 下载用户消息里的图片或文件 | [获取消息中的资源文件](https://open.feishu.cn/document/server-docs/im-v1/message/get-2)：开通该接口列出的消息读取权限之一，例如获取单聊、群组消息；不要误用仅下载机器人自身上传图片的接口 |
| 上传待发送图片 | [上传图片](https://open.feishu.cn/document/server-docs/im-v1/image/create)：开通“获取与上传图片或文件资源”等当前列出的可用权限 |
| 上传待发送文件、视频或音频 | [上传文件](https://open.feishu.cn/document/server-docs/im-v1/file/create)：开通“获取与上传图片或文件资源”等当前列出的可用权限 |
| 将上传资源回复给当前消息 | [回复消息](https://open.feishu.cn/document/server-docs/im-v1/message/reply)：保留应用身份回复消息所需权限 |

在飞书「权限管理」中按照上述接口的权限要求开通，再完成版本创建、发布和审批生效。旧版权限不一定仍能新增申请，名称或可选权限变动时以当前接口页及后台提示为准；无需为附件申请与任务无关的通讯录、文档编辑等权限。更新权限后用实际附件测试，应用凭据测试成功不能替代资源 API 验收。

## 4. 设置字段说明

| 设置项 | 用途与填写规则 |
| --- | --- |
| 连接方式 | 决定使用 Webhook 或长连接，保存后生效。 |
| App ID | 飞书企业自建应用的标识，在「凭证与基础信息」取得。 |
| App Secret | 应用密钥，用于向飞书认证及获取应用访问令牌；与 Verification Token 是不同凭据。 |
| Verification Token | 飞书事件中的校验令牌，用于核对请求是否属于你的应用。Webhook 接收普通消息时需有 Token 校验或加密签名校验。 |
| Encrypt Key | 飞书启用事件加密时使用的密钥，插件据此解密载荷并验证普通加密事件的签名。必须与飞书后台一致，不是自行填写的登录密码。 |
| 项目目录 | 点击「搜索项目」，按名称或路径筛选 Harness 已添加的项目及已绑定目录；选定后保存。目录须存在、可访问且未被其他机器人占用。远程 Agent 仅能操作该项目下所属用户的 `.feishu-users/` 子目录。 |
| 每日上下文切换时间 | 整数 0–23，默认 `4`；任务执行中会推迟到完成后切换。 |
| 每日上下文切换时区 | 有效 IANA 时区，默认 `Asia/Macau`；切换归档旧会话，SQLite 历史与 Harness 归档日志继续保留。 |
| Agent 预设 | 当前 Harness 已安装的预设名称，默认 `standard`。 |
| 权限预设 | 仅支持只读（`read-only`）和工作区写入（`workspace-write`，默认）；禁止完全访问。远程会话仅开放受限文件、历史及当前消息附件工具，无任意 Shell、通用 MCP 或跨用户飞书 API。 |
| 公网接入方式 | Webhook 下选择 ngrok（默认）、Cloudflare Tunnel 或自定义公网地址，保存后生效。长连接不需要任何隧道。 |
| 公网服务地址 | 填写 HTTPS 根地址。ngrok 可留空使用自动检测结果；插件托管的 Cloudflare Quick Tunnel 显示本次生成地址；固定域名、外部 Cloudflare 和自定义模式需填写。 |
| Webhook 地址 | 只读显示，由公网服务地址和插件路径组合；复制到飞书后台的请求地址栏。 |

**测试连接** 会使用当前填写的 App ID / App Secret 向飞书进行应用认证；输入留空时使用已保存值。测试成功不会保存修改，也不代表事件订阅或消息回复已经接通，仍需点击 **保存配置**。

App Secret、Verification Token、Encrypt Key 不会回显；出现「已保存凭证」时，输入框为空是正常现象。**留空表示保留旧值，填写新值表示替换**，不是清空已保存凭据。

凭据通过 Harness 凭据服务保存，普通配置保存在 `DSH_HOME` 下的 `feishu-bot.json`。默认凭据引用为 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_VERIFICATION_TOKEN` 和 `FEISHU_ENCRYPT_KEY`。若值来自进程环境变量，页面不能覆盖成不同值；应修改启动环境并重启 Harness。

## 5. 姓名确认与会话管理

1. 在飞书后台设置应用可用范围，完成事件订阅和回复权限。插件无需预填用户 `open_id` 或姓名。
2. 首次向机器人发送消息时，先进入姓名确认。按提示回复自己的姓名，例如 `Alex`、`我叫Alex` 或 `/name Alex`。
3. 机器人复述待确认姓名后，单独回复 **`确认`**。只有完成这一步，才能开始普通对话；如果姓名不正确，先回复 `/name 正确的名字`，再确认。
4. 重新发送实际任务。确认前的问题不会排队等待，也不会在确认后自动执行。

姓名确认由插件在调用 Agent 前处理。未提供或未确认姓名时，机器人只继续要求提供或确认姓名，不回答其他问题；`/new`、`/status`、`/whoami`、`/help` 也不能跳过该步骤。此流程只确认用户希望使用的称呼，不验证真实姓名，也不赋予其他用户的数据权限。

确认结果保存在用户资料中，重启 Harness、`/new` 和每日上下文切换都不会清除。升级前在旧名单中设置过姓名的用户，也需要亲自完成一次确认；旧名单不会被当作确认结果。

新用户采用所属机器人的权限预设，仅支持只读或工作区写入。旧配置中已有的个人权限覆盖会继续保留，但不再作为准入名单。输入文件可通过飞书上传，或由本机管理员放入对应用户子目录；远程用户没有通用 Shell、任意主机文件读取或通用 MCP 权限。数据库分开本身不是操作系统级账号或虚拟机隔离。

以下命令在姓名确认完成后可用：

| 飞书命令 | 行为 |
| --- | --- |
| `/whoami` | 查询自己的飞书身份。 |
| `/help` | 查看插件命令说明。 |
| `/status` | 查看当前聊天的会话状态。 |
| `/new` | 旧任务完成后归档旧会话，下一条消息进入新上下文；保留 SQLite 历史、Harness 归档日志和工作文件。 |

在 Harness 界面删除飞书 workspace 只会移除工作区注册，下一条普通飞书消息会恢复工作区并继续原会话；这与 Archive 后新建会话不同。若直接删除磁盘工作目录，插件只能重建空目录，无法恢复已删除的工作文件；独立存放的历史数据库不受仅删除工作目录影响。

在 Harness 中手动 Archive 当前飞书会话后，下一条普通飞书消息会创建可见的新会话。旧会话保持归档，历史仍可查询；若旧任务仍在运行，则等它完成后再切换。归档会开启新的上下文，不会自动复制旧上下文。`/status` 可查看当前会话是否已归档。

同一机器人中的同一用户同一时间最多拥有一个当前可见的 Harness 会话。同一聊天中的追问默认复用该会话；切换到其他群聊或私聊时，先等待旧任务完成并归档上一个聊天的会话，再创建新上下文，避免混用聊天内容。不同用户不会共享会话；历史工具仍按当前用户、当前聊天隔离。

默认每天 **Asia/Macau 04:00** 归档旧会话，若任务仍在执行则等待结束；下一条消息开启新上下文。无需新消息触发，SQLite 历史、Harness 归档日志和工作文件继续保留。重启会补归档已经关闭但仍留在当前列表的记录；旧数据库缺少身份资料时，首次通过验证的飞书消息会自动补齐，此后无人发消息也能定时切换。需要其他时间或时区时，在设置中修改并保存。

### 历史数据库与权限边界

每位用户按来源、租户与稳定用户身份使用独立 SQLite 数据库，记录消息时间戳及会话关联。确认的姓名保存为用户资料，用于会话标题，不作为数据库或工作目录名称；两个人使用相同姓名也不会合并数据。Agent 历史工具进一步限制为**当前用户、当前聊天**。可通过自然语言请求搜索、读取、新增笔记、更正或软删除历史，例如“查找本聊天上个月讨论的计划，并给出时间”。来自另一个群的内容不会因属于同一用户就自动暴露到当前群。

历史修改和软删除不会追溯修改飞书原消息、Harness 原会话日志或已经送入模型的上下文。删除后如需刷新上下文，请再发送 `/new`；这仍不等于从整机备份与其他日志彻底擦除数据。本机管理员可访问实际数据库和工作区，应独立管理主机账号、备份与磁盘权限。

历史库不是持久任务队列，处理中重启不能保证补发答复。旧版按消息创建的会话不会自动导入新历史库。每日切换功能也不提供任意 cron 或定时任务执行器。

### 附件收发与历史图片

姓名确认完成后，可以在原聊天上传文件、图片、视频、音频，或发送包含图片的图文消息（`post`）。两种连接方式支持相同资源类型，不用再添加事件订阅、安装其他模型或修改 Harness 核心。未确认姓名时插件不下载附件，只继续确认姓名；请确认后重发。

接收的文件保存为个人工作目录中的 `incoming/...`，历史记录保留原名、接收时间和相对路径。每条消息最多 10 个资源，合计不超过 100 MiB；图片进入模型还需满足 Harness 当前图片格式、尺寸及数量限制。历史可按名称、时间搜索，`/new` 与凌晨切换不会删除文件。手动删除工作目录中的文件后，仅有数据库记录不能恢复文件内容。

Agent 可使用：

| 工具 | 用途与参数 |
| --- | --- |
| `workspace_write` | 在有工作区写入权限时生成 TXT、Markdown、CSV 等文本文件 |
| `feishu_read_image` | 读取自己工作目录中的图片，包括历史路径；当前模型必须明确支持图片输入 |
| `feishu_send_file` | `path` 为个人目录内的相对路径；`kind=file\|image\|video\|audio`，默认 `file`；可选 `coverPath` 指定视频封面，`duration` 单位为毫秒 |

发送图片上限为 10 MiB，文件、视频和音频均为 30 MiB。`kind=video` 仅支持 MP4，`kind=audio` 仅支持 OPUS；其他格式用 `kind=file` 发送，插件不自动转码。视频封面也必须位于自己的工作目录。发送工具只回复当前已领取的飞书消息，没有收件人参数；不能从空闲 Harness 会话任意发送，也不能发送其他用户目录中的文件。

例如可以说“将这个 CSV 整理成 Markdown，保存为 `outputs/summary.md` 并发给我”。只读权限下不能生成或修改工作区文件。纯文本模型可以保存、查找和发送图片文件，但不能看图；插件不内置 OCR、视频分析、语音转写、转码或通用 PDF/Office 解析，也不开放任意 Shell。

## 6. 验收消息与会话

1. 在 Harness 网页中发起普通会话，确认模型可以答复。
2. 确认插件配置已保存，Webhook 地址通过验证或长连接显示已连接。
3. 首次消息应触发姓名确认；确认前发送普通问题或 `/new`，都应只收到姓名提示，不能执行任务。提供姓名并回复 `确认` 后，重新发送 `请只回复：飞书连接正常`。
4. 确认 Harness 出现包含用户确认姓名的会话，并生成答复。
5. 确认机器人在飞书回复了这次请求。若需要群聊，再单独测试群内 @机器人。
6. 开通表情写权限后，用一条耗时稍长的文本任务检查原消息上的敲键盘表情是否在处理期间出现、结束后移除；快速完成的任务可能不易观察。
7. 继续追问应沿用会话；`/new`、日切或换到另一个群聊/私聊后，旧会话应归档，后续消息使用新上下文，每位用户最多一个当前可见会话。验证忙任务先完成、历史可查；再用两个用户检查姓名、上下文、目录和历史互不混用。
8. 请求 Agent 查找刚才的历史记录及时间，检查当前聊天之外的记录无法访问。用两个相同姓名的用户验证数据仍独立，并验证重启、`/new` 和每日切换后无需重复确认姓名。
9. 从飞书侧检查不在应用可用范围内的账号无法按预期使用机器人。插件不承诺撤回飞书访问范围会实时取消已经运行的任务。
10. 上传小型 TXT/CSV、图片、MP4、OPUS 及含图片的图文消息，确认保存路径与历史原名、时间；要求发送文件回来，确认飞书收到实际附件而不只是路径。分别用支持图片和纯文本的模型检查能力提示。
11. 发送 `/new` 后按文件名检索旧附件；确认可访问本用户文件，而无法发送其他用户目录的文件。

默认在 Agent 完成后回复最终文本；附件由相应工具在当前任务中发送，没有流式进度卡片。

工作状态表情默认自动启用，目前没有独立开关。任务完成、出错、取消或插件卸载时，插件会尝试移除自己添加的表情，不会删除他人的回应。状态更新失败只记录日志，不影响任务和最终答复；断网或强制终止进程可能导致表情残留。

自动测试及本地检查不能代替 0.2.0 的真实飞书多用户收发验收；三平台完整链路仍需各自验证。完成上述步骤后，才能确认你自己的应用、权限、网络和模型组成的完整链路可用。

## 启动参数与更新

### 平台与端口

插件核心使用 Node.js，面向 Linux、Windows 和 macOS。安装器在 Windows 使用目录 junction，在 Linux/macOS 使用符号链接。各系统均可运行本文的 `npm run` 命令；Windows 建议使用 PowerShell。Bash 的 `alias` 不是插件依赖，也不能直接粘贴进 PowerShell。

Windows 可先在 Harness 添加 `C:\Projects\my-project`，Linux/macOS 添加各自本机项目目录，再在插件的项目列表中选择；路径中有空格时，在命令行中用引号包裹。ngrok 和 cloudflared 需要安装对应系统版本，并加入 PATH。插件不会自动安装这些程序。

目前本机验证环境是 Linux。CI 配置覆盖三种系统的自动测试，但真实飞书收发、隧道连通和后台进程行为仍需在目标系统验收；不能仅凭代码兼容认定三平台所有场景均已通过。

Harness 与飞书回调共用同一个监听端口。插件会自动获取该端口，无需再保存一个可能不一致的副本；修改监听端口需要重启 Harness，并同步调整隧道目标。

### 启动命令

在插件源码目录运行，默认以前台方式启动 Harness，日志显示在当前终端：

```bash
npm run start:harness
```

脚本向 `dsh web` 透传启动参数，可指定其他端口或使用后台运行：

```bash
npm run start:harness -- --port 3081
npm run start:harness -- --background
```

后台运行时，日志位于插件目录的 `.runtime/harness.log`。`--background` 只检查进程启动后短时间内是否退出，需通过日志确认服务实际就绪。若已有实例占用端口，请在其原启动终端停止后再启动，脚本不会自动停止已有服务。

脚本优先使用 `DSH_BIN` 指定的入口，其次查找 PATH 中的 Harness 入口和已有 npm npx 缓存；Windows 会读取 npm 安装目录中的 JS 入口，避免执行 shell shim。如果提示未找到 Harness，先确认官方程序已安装；也可以通过启动环境中的 `DSH_BIN` 指定 JavaScript 入口或原生可执行文件。Windows 上不要将 `DSH_BIN` 指向 `.cmd` / `.bat`，当前脚本不支持这两种入口。

ngrok 也支持后台运行，日志位于 `.runtime/ngrok.log`：

```bash
npm run start:ngrok -- --url https://YOUR-NGROK-DOMAIN --port 3080 --background
```

Cloudflare 启动脚本也支持 `--background`，日志位于 `.runtime/cloudflared.log`。后台启动只表示进程没有立即退出，不表示隧道已经连通：

```bash
npm run start:cloudflare -- --port 3080 --background
```

Quick Tunnel 的公网域名仍需从日志中复制到插件，再同步飞书后台的完整回调地址。

**升级到当前版本时：**先核对飞书后台的应用可用范围。插件不再使用旧的 `authorizedUsers` 作为准入名单，其中已有的个人 `permissionPreset` 仅为兼容继续保留。所有用户首次使用新版时都需亲自提供并确认姓名，旧配置中的姓名不代表已确认。确认 Node.js 至少为 22.13；旧配置中的 `danger-full-access` 必须改为 `read-only` 或 `workspace-write`。远程会话不再开放旧版的通用工具能力，旧版逐消息会话不会自动合并或导入数据库。

更新仓库源码后，运行 `npm ci` 和 `npm run install:harness`，再重启 Harness。若使用自定义 `DSH_HOME`，更新安装与启动时也应保持一致。

## 存储与信任边界

历史数据库位于 `DSH_HOME/feishu-history/<身份哈希>/history.sqlite`（未设置 `DSH_HOME` 时使用本机 `~/.dsh`）。工作文件位于配置的工作目录根下 `.feishu-users/<身份哈希>/`。哈希由来源、租户与用户 ID 计算，不使用姓名作为路径。

同一用户跨聊天切换时归档旧 session、创建新上下文，数据库检索仍按聊天分开，但共享该用户的工作文件。不要把“按聊天限制历史检索”理解为“同一用户的私聊与群聊文件也完全分开”。

隔离面向远端飞书用户，不限制本机系统管理员。Harness 原始会话日志仍由 Harness 统一持久化，因此管理界面只应向可信管理员开放。插件禁用后由管理员手动打开旧会话，不能依赖已禁用插件继续施加工具限制；需要操作系统级隔离时应使用独立实例、系统账号或容器。

新消息在等待旧任务或创建模型会话之前保存原文。已经进入 Harness 持久队列的消息可恢复回复关联；若进程在进入队列之前退出，原文仍可检索，但不会自动重放，以免重复执行文件修改等操作。模型执行失败也应查看对应会话记录后再决定是否重发。
