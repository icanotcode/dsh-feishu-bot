## dsh-feishu-bot：在飞书中使用 DeepSeek Harness

开源了一个 DeepSeek Harness 飞书机器人插件，只保留 Harness 插件列表入口：在 **设置 → 插件 → Plugin list** 搜索 `feishu`，展开 **Global plugins** 中的 `feishu-bot` 卡片即可配置。通过飞书发送文本任务，由本机 Harness Agent 执行，再把最终文本答复发送回原消息。

提供两种可切换的接入方式：

- **开发者服务器 Webhook**：适合已有公网 HTTPS 入口、ngrok 或 Cloudflare Tunnel 的场景，支持飞书地址验证、Token 校验和加密请求处理。
- **长连接 WebSocket**：本机主动连接飞书，不需要公网地址或任何隧道。

卡片内的配置表单可保存应用凭据，选择用户工作目录根路径、Agent 和权限预设，测试应用认证并查看连接状态。仓库提供中文/英文说明、安装步骤、飞书接入和常见问题指南。

默认延续同一用户在同一聊天中的会话，用用户亲自确认的姓名命名。支持 `/new` 新开上下文、`/status` 查看状态、`/help` 查看命令、`/whoami` 查询身份。`/new` 不终止旧任务，新的任务会等待旧任务结束。不同用户、不同群聊与私聊分别维护上下文。

用户接入范围由飞书后台管理，插件无需预填 `open_id` 或用户名。首次聊天先询问姓名；用户回复姓名后还需回复“确认”，才能执行任务或使用会话命令。确认前只处理姓名确认，之前的问题需确认后重新发送。确认结果跨重启、`/new` 和每日切换保留，旧版用户也需亲自确认一次。

每位用户拥有独立工作目录和按来源、租户、用户稳定身份分开的 SQLite 数据库；姓名用于资料和会话标题，同名用户不合并数据。远程会话仅开放个人工作区文件工具与历史工具，不开放任意 Shell、通用 MCP 或跨用户飞书 API；权限只支持只读与工作区写入，新用户继承全局默认，旧配置中的个人权限覆盖保留。

历史消息保留时间戳，Agent 可查询、读取、新增笔记、修改或软删除当前用户在当前聊天中的记录。默认每天 Asia/Macau 凌晨 4 点切换新上下文，任务未完成则等待结束，历史继续保留。历史修改不追溯改变 Harness 原会话日志、飞书消息或已加载上下文；需要刷新上下文时可再发送 `/new`。

处理开始时，机器人会在原消息添加敲键盘（`Typing`）表情回应，结束时尝试清除；需要表情回复写权限，权限不足不影响正常处理与回复。此功能不要求订阅用户的表情回应事件。

面板支持 ngrok / Cloudflare 一键启动与隧道守护滑动开关，使用 Harness 当前实际端口，支持 Linux、Windows、macOS 原生程序。Cloudflare 支持临时 Quick Tunnel 和现有本地管理的固定命名隧道；需先安装程序并准备相应账户配置。守护随 Harness 运行，异常退出会退避重试，只停止自己托管的进程。临时域名改变后仍需手动更新飞书回调地址。

当前版本 **0.2.0**，使用 MIT 许可证，通过 GitHub 源码安装，尚未发布到 npm。兼容验证基于 Harness `0.1.5-rc.2` 的 Web profile，需要 Node.js **22.13 或更新版本**，历史存储使用内置 `node:sqlite`。升级时请核对飞书应用可用范围、完成姓名确认并移除旧的完全访问权限；旧会话不会自动合并或导入历史库。

支持文本输入、连续多轮会话与最终文本回复；暂不支持图片/文件输入、流式回复、卡片按钮回调或通用定时任务。每日上下文切换不是任意 cron 执行器，SQLite 历史也不是可靠投递队列，处理中重启不保证补发答复。已有自动测试及本地检查，0.2.0 真实飞书多用户收发与三平台完整链路仍需验收，欢迎试用反馈。
