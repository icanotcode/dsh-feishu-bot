## dsh-feishu-bot：在飞书中使用 DeepSeek Harness

开源了一个支持“一台 Harness 服务器连接多个飞书机器人、每个机器人对应一个项目”的插件，只保留 Harness 插件列表入口：在 **设置 → 插件 → Plugin list** 搜索 `feishu`，展开 **Global plugins** 中的 `feishu-bot` 卡片即可配置。通过飞书发送文本、图文和附件任务，由本机 Harness Agent 执行，再把答复与文件发送回原消息。

提供两种可切换的接入方式：

- **开发者服务器 Webhook**：适合已有公网 HTTPS 入口、ngrok 或 Cloudflare Tunnel 的场景，支持飞书地址验证、Token 校验和加密请求处理。
- **长连接 WebSocket**：本机主动连接飞书，不需要公网地址或任何隧道。

卡片顶部可选择、添加、重命名和启用/停用机器人；每个应用使用不同的 App ID 和独立项目目录。卡片内的配置表单可保存应用凭据，通过搜索下拉框选择项目目录、设置 Agent 和权限预设，测试应用认证并查看连接状态。项目列表来自 Harness 已添加项目和机器人已绑定目录，按名称或路径实时筛选，不扫描磁盘；被其他机器人占用或无法访问的目录不可选。找不到项目时，先在 Harness 添加，再刷新列表。选择项目不会扩大远程用户权限，每人仍仅能访问项目下自己的 `.feishu-users/` 目录。仓库提供中文/英文说明、安装步骤、飞书接入和常见问题指南。

每个机器人中的每位用户同一时间最多一个当前可见的 Harness 会话，用亲自确认的姓名命名。同一聊天延续上下文；`/new` 或切换群聊/私聊会在旧任务完成后归档上个会话，再开启新上下文。支持 `/status` 查看状态、`/help` 查看命令、`/whoami` 查询身份；不同用户独立，历史工具仍按聊天隔离。

用户接入范围由飞书后台管理，插件无需预填 `open_id` 或用户名。首次聊天先询问姓名；用户回复姓名后还需回复“确认”，才能执行任务或使用会话命令。确认前只处理姓名确认，之前的问题需确认后重新发送。确认结果跨重启、`/new` 和每日切换保留，旧版用户也需亲自确认一次。

不同机器人的凭据、姓名资料、会话、数据库及附件分开，同一人在不同机器人中独立确认姓名。每位用户拥有独立工作目录和按来源、租户、用户稳定身份分开的 SQLite 数据库；姓名用于资料和会话标题，同名用户不合并数据。远程会话仅开放个人工作区文件、历史、当前消息附件及个人邮箱工具，不开放任意 Shell、通用 MCP 或跨用户飞书 API；权限只支持只读与工作区写入，新用户继承所属机器人的默认权限，旧配置中的个人权限覆盖保留。

历史消息保留时间戳，Agent 可查询、读取、新增笔记、修改或软删除当前用户在当前聊天中的记录。默认每天 Asia/Macau 凌晨 4 点归档旧会话，任务未完成则等待结束，下一条消息开启新上下文；保留 SQLite 历史、Harness 归档日志和文件。重启会补归档已关闭的遗留记录；旧数据库在首次验证消息中补齐身份后，无新消息也能定时切换。历史修改不追溯改变 Harness 原会话日志、飞书消息或已加载上下文；需要刷新上下文时可再发送 `/new`。

处理开始时，机器人会在原消息添加敲键盘（`Typing`）表情回应，结束时尝试清除；需要表情回复写权限，权限不足不影响正常处理与回复。此功能不要求订阅用户的表情回应事件。

所有 Webhook 机器人共享一个公网隧道，默认机器人下的面板支持 ngrok / Cloudflare 一键启动与隧道守护滑动开关，使用 Harness 当前实际端口，支持 Linux、Windows、macOS 原生程序。Cloudflare 支持临时 Quick Tunnel 和现有本地管理的固定命名隧道；需先安装程序并准备相应账户配置。守护随 Harness 运行，异常退出会退避重试，只停止自己托管的进程。默认机器人即使使用长连接，也能在其他机器人需要 Webhook 时管理这个共享隧道。各应用有独立回调 URL，请分别复制面板地址；临时域名改变后仍需逐一更新飞书回调地址。

当前版本 **0.2.0**，使用 MIT 许可证，通过 GitHub 源码安装，尚未发布到 npm。兼容验证基于 Harness `0.1.5-rc.2` 的 Web profile，需要 Node.js **22.13 或更新版本**，历史存储使用内置 `node:sqlite`。升级时请核对飞书应用可用范围、完成姓名确认并移除旧的完全访问权限；旧会话不会自动合并或导入历史库。

支持文本、含图片的图文（`post`）、图片、文件、视频与音频输入。每条最多 10 个资源、合计 100 MiB，存入个人 `incoming/...`，历史保留原名、时间与相对路径；`/new` 和每日切换不删除文件，未确认姓名不下载附件。

Agent 可通过 `feishu_send_file(path, kind, coverPath?, duration?)` 回复当前消息：图片上限 10 MiB，文件、视频、音频上限 30 MiB；视频类型仅 MP4、音频类型仅 OPUS，其他格式可作为普通文件发送，时长单位为毫秒。发送仅在当前已领取的飞书任务中可用，无任意收件人参数。工作区写入权限可生成 TXT/Markdown/CSV 后发回。

`feishu_read_image` 可读取个人目录历史图片，但当前模型必须明确支持图片输入；纯文本模型只保存文件。收发视频/音频不代表自动理解内容，不包含 OCR、转写、转码、视频分析或通用 PDF/Office 解析。这些能力无需修改 Harness 核心或添加模型，也不增加面板入口。按接入指南开通资源 API 权限并发布应用后使用。

升级前的应用继续作为默认机器人，保留原回调路径、凭据和历史。重命名不改变身份或数据；停用保留配置及历史，忙碌时会拒绝停用，等任务完成后再操作。

支持个人邮箱通过自定义 SMTP 服务发信，不支持收信。普通聊天照常；用户完成姓名确认后，首次要求发邮件或在机器人私聊发送 `/mail` 才进入配置，输入本人邮箱后，已知服务商快速匹配，未知域名由 Agent 通过专用发现工具在线查询 DNS 邮件提交记录、域名官方 HTTPS 自动配置和 Thunderbird ISPDB，并先进行不携带授权码的 TLS／SMTP 连接探测，再询问授权码；用户不需填写服务器、端口或加密方式。发现只使用域名，不向配置服务外发完整邮箱或授权码，不把 MX 当发信地址，并拒绝私网及重定向绕过。无可靠配置或网络不通时说明暂时无法完成，保留当前发送任务，可用 `/mail retry` 重查；不保证任意域名都能识别，仍保留高级手动覆盖，不支持 OAuth 登录。授权码按机器人、租户和稳定用户身份分别保存到 Harness credentials，在进入 Webhook 投递、历史和模型前脱敏；插件不会清除飞书原始聊天记录。发件人和收件人固定来自本人的绑定，邮件可带最多 10 个个人目录附件，估算 MIME 总体积不超过 10 MiB。因明确发信请求进入配置时，保留当前请求及已明确的收件人，验证成功后继续任务，仅补问缺失内容，无需重复发送指令。手动配置不会自动发信，取消或重置丢弃待办，不重放历史草稿。SMTP 接受不代表送达，不确定失败不自动重发；尚未完成真实外部邮箱收件验收。

插件读取轻量的 `skills/feishu-assistant/SKILL.md`，将指引加入每条进入 Agent 的飞书消息，无需另行安装 Skill；姓名确认、邮箱配置与授权码保护由入口状态机处理。邮件命令包括 `/mail setup`、`/mail status`、`/mail retry`、高级 `/mail server`、`/mail code`、`/mail to 地址`、`/mail reset` 和 `/mail cancel`，无须新增面板入口。

暂不支持流式回复、卡片按钮回调或通用定时任务。每日上下文切换不是任意 cron 执行器，SQLite 历史也不是可靠投递队列，处理中重启不保证补发答复。已有自动测试及本地检查，0.2.0 真实飞书多用户收发与三平台完整链路仍需验收，欢迎试用反馈。
