# 故障排查与常见问题

[返回项目首页](../README.md) · [飞书接入指南](setup.md)

先定位问题发生在哪一步：插件加载 → 配置保存 → 事件到达 → Harness 处理 → 飞书回复。应用认证成功、长连接建立和地址验证成功，分别验证其中一部分，不能代替完整消息测试。

## 插件没有显示，或设置页打不开

1. 确认在克隆的插件目录运行过 `npm ci` 和 `npm run install:harness`，然后重启了 Harness。
2. 确认当前启动的是安装时使用的 `web` profile；自定义 `DSH_HOME` 必须在安装和启动时一致。
3. 打开 **设置 → 插件 → Plugin list**，搜索 `feishu`，检查 **Global plugins（全局插件）** 中的 `feishu-bot` 是否已启用，展开卡片查看配置表单。全局分组默认折叠；搜索可显示匹配项。插件不再提供独立的飞书标签页或侧栏入口。
4. 如果移动或删除了源码目录，安装链接可能失效。保留源码目录，重新运行安装脚本并重启。
5. 使用 Node.js 22.13 或更高版本；更早版本可能无法加载内置 `node:sqlite`。检查启动日志中的依赖或插件加载错误。当前兼容验证基于 Harness `0.1.5-rc.2` 相关组件；其他版本接口变化可能影响加载。

当前 Harness 的 Plugin list 是只读清单，未提供卡片配置的官方扩展槽位。本插件通过卡片的 `data-*` 属性定位并挂载配置表单。若升级 Harness 后仍能看到插件卡片，却无法显示表单，请关闭并重新打开设置；若仍无效，请在 issue 中提供 Harness 版本和浏览器报错，勿附带凭据。

安装脚本遇到已有同名插件、旧版作用域插件或不兼容链接时，会报告冲突。先核对报错所指的配置和自动备份，再处理旧安装；不要直接删除整个 Harness 配置目录。

## 多机器人无法新增、凭据冲突或找不到隧道开关

- **新增失败**：名称不能为空，项目目录必须是本机已有的绝对目录，不能与其他机器人重复。每个机器人需要独立飞书应用和 App ID，停用的机器人也仍保留自己的配置；不能靠新增一条相同应用配置来复制项目。
- **其他机器人没有隧道开关**：这是服务器共享设置，请在顶部选择默认机器人。默认机器人即使使用长连接，只要其他启用的机器人使用 Webhook，仍可在默认机器人下管理隧道。
- **一个机器人收不到事件**：先确认顶部选中的是对应应用、已启用且凭据正确，再将其完整 Webhook URL 填入该飞书应用。新增机器人的 URL 有独立子路径，不能复用默认 `/webhook/feishu`；重命名不会改变地址。
- **停用失败**：机器人有任务运行时不会被强制停止，开关保留原状态。等任务结束后重试；停用成功后配置、历史及附件均保留。
- **同一人在列表里有两条会话**：先看它们是否属于不同机器人。限制是“每个机器人中的每用户最多一个当前会话”，不同机器人的项目与历史应独立；同一机器人中日切或 `/new` 产生的旧会话会被归档。
- **换机器人后找不到旧姓名或附件**：新增机器人有独立资料和项目目录，需要单独完成姓名确认；升级前的数据仍在默认机器人中，不会复制到新机器人。

## 保存飞书请求地址时提示「3 秒超时」

插件处理地址验证时直接返回 `challenge`，不等待 Agent 或模型。飞书提示超时，也可能是请求没有到达正确路径、被代理拦截，或者返回了错误响应。按以下顺序检查：

1. **服务是否仍在运行。** 用启动日志提供的本机地址打开 Harness。若进程已退出，先查看退出原因。
2. **隧道端口是否正确。** ngrok、Cloudflare Tunnel 或自定义代理必须指向当前 Harness 监听端口，例如 `3080`；转发到其他本地服务不会自动到达 Harness。
3. **飞书请求地址是否完整。** 默认机器人应为 `https://your-domain.example/webhook/feishu`；新增机器人复制它自己面板中的独立子路径地址，不能只填域名或其他机器人的 URL。
4. **当前模式是否已保存为 Webhook。** 仅修改下拉框未保存不会切换模式；长连接模式下该入口返回 `409`。
5. **请求是否被登录或代理策略拦截。** 检查隧道/代理记录和 Harness 日志；使用 Cloudflare 时也检查 Access 等访问策略。若看到登录跳转或 HTML 页面，飞书收到的不是验证响应。
6. **Token / Encrypt Key 是否已先保存。** 启用加密时缺少 Encrypt Key 会返回 `503`，密钥错误可能返回 `400`，Token 不一致会返回 `401`。先保存正确值，再到飞书重新保存地址。

使用 ngrok 时，可在本机检查 `http://127.0.0.1:4040` 的请求记录。重点看目标路径、返回状态和响应类型；不要把包含凭据或消息正文的完整请求记录公开分享。

如果 ngrok 能看到请求而 Harness 没有对应记录，优先检查隧道上游端口和代理策略。如果 Harness 已立即返回错误，应先解决该状态码指向的问题。

## 为什么域名后面需要 `/webhook/feishu`？

域名决定请求送到哪台服务，路径决定服务内部哪个处理器接收请求。默认链路是：

```text
飞书 POST https://your-domain.example/webhook/feishu
  → ngrok / Cloudflare / 自定义代理转发至 http://127.0.0.1:3080/webhook/feishu
  → Harness 的飞书 Webhook 处理器
  → 返回地址验证结果，或把文本事件交给 Agent
```

隧道通常会保留请求路径。只填写域名时，请求路径是 `/`；即使请求已经到达 Harness，也不会自动转交给注册在 `/webhook/feishu` 的处理器。浏览器能打开 Harness 首页，同样不能证明飞书事件入口配置正确。

只有服务本身在根路径处理飞书 POST 请求，或者代理已明确把根路径改写到 `/webhook/feishu` 时，飞书后台才可以只填域名。本插件默认没有这种改写，直接使用完整 Webhook URL 即可，无需额外配置根路径转发。

插件的 **公网服务地址** 输入框则应只填域名根地址，因为页面会自动拼接路径，生成用于飞书后台的完整 **Webhook 地址**。

## Webhook 状态码怎么看？

以下含义对应插件自身的响应；ngrok、Cloudflare 或其他代理也可能返回相同状态码，应结合响应正文与请求记录判断来源。

| HTTP 状态 | 常见含义 | 检查方法 |
| --- | --- | --- |
| `200` | 请求已应答；地址验证时返回 `challenge` | 普通事件被应答不代表 Agent 已完成，未支持的事件也可能被忽略后应答。 |
| `400` | JSON、事件标识、加密载荷或签名头有误 | 检查是否为飞书原始请求、Encrypt Key 是否匹配，以及代理是否改写了请求体或签名头。 |
| `401` | Verification Token 或加密签名不匹配 | 检查是否复制了同一个应用的值，保存后再验证。 |
| `405` | 不是 POST 请求 | 在浏览器地址栏打开 URL 是 GET；看到此状态不能用来判断飞书 POST 验证失败。 |
| `409` | 当前已选择长连接，Webhook 入口关闭 | 需要 Webhook 时，切换模式并保存，同时修改飞书后台订阅方式。 |
| `413` | 请求体超过允许大小 | 检查代理请求记录与插件配置，排除异常载荷。 |
| `415` | 请求不是支持的 JSON 内容类型 | 飞书请求应使用 JSON；检查代理是否改写 `Content-Type`。 |
| `503` | 缺少加密/认证配置，或事件运行时不可用 | 检查 Encrypt Key、Verification Token，以及 Harness 的插件依赖和启动日志。 |

收到 `404`、登录重定向或 HTML 页面时，优先检查公网路径、反向代理和插件是否正确加载。

## Verification Token 和 Encrypt Key 到底填什么？

它们属于飞书后台 **事件与回调 → 加密策略**，与 **凭证与基础信息** 中的 App ID / App Secret 不同。

- **App Secret**：插件向飞书证明应用身份，用于调用应用 API、获取访问令牌和建立长连接。
- **Verification Token**：Webhook 中用于核对事件来源的校验令牌。
- **Encrypt Key**：启用事件加密时，用于解密请求，并校验普通加密事件的签名。

使用 Webhook 接收普通消息时，至少需要有效的 Token 校验或加密签名校验；若同时配置 Token，也会检查 Token。使用长连接时不需要填写 Verification Token 或 Encrypt Key。

设置页不回显密钥值，留空会保留旧值。若要替换，请填写新值并保存。环境变量提供的凭据不能在页面中覆盖为不同值，需要修改启动环境并重启。

## 「测试连接成功」，为什么机器人仍不回复？

「测试连接」只调用飞书应用认证接口，检查 App ID 和 App Secret。它不保存配置、不订阅事件，也不测试模型或回复权限。请按症状继续定位：

| 现象 | 下一步 |
| --- | --- |
| Harness 中没有飞书会话 | 先完成机器人要求的姓名确认，再重新发送任务；若连姓名提示都未收到，检查应用可用范围、接收模式、`im.message.receive_v1`、应用发布和消息权限。 |
| 私聊有反应，群聊没有 | 确认机器人已入群，群消息接收权限生效，并在群内 @机器人。 |
| 会话出现但执行失败 | 查看该会话中的错误，核对模型凭据、工作目录、Agent 预设及权限预设。 |
| Harness 已有答复，飞书没有 | 检查飞书回复权限、应用认证和网络；自动回复失败时，答复仍保留在 Harness 会话中。 |
| 只发图片、文件、视频或语音没有反应 | 先完成姓名确认并重发，再检查附件权限、大小上限与 Harness 会话中的资源处理提示。 |
| 后一条消息不记得前文 | 确认未执行 `/new`、每日切换或切换到其他群聊/私聊；跨聊天切换会归档旧上下文，返回原聊天也会新开上下文。旧内容可要求 Agent 查询当前聊天历史。 |

完成姓名确认后，最小测试可以发送 `请只回复：飞书连接正常`，同时观察 Harness 会话和飞书回复。不要仅根据设置页某一个「成功」状态判断完整链路已通过。

## 为什么机器人一直问姓名，不回答问题？

这是首次对话的必经步骤。回复 `Alex`、`我叫Alex` 或 `/name Alex`，核对待确认姓名后单独回复 `确认`。仅提供姓名还没有完成确认。完成前的普通问题和 `/new`、`/status`、`/whoami`、`/help` 都不会被执行，插件只继续确认姓名；确认后请重新发送任务，之前的问题不会自动恢复执行。

确认结果跨重启、`/new` 和每日切换保留。旧版管理员预填过姓名的用户也必须亲自确认一次。如果每次都重新询问，检查是否更换了飞书应用、租户、用户身份或 `DSH_HOME`，以及历史存储是否可写并持久保存。

## 升级后仍显示未授权，或以前能执行的命令失效

当前版本不再要求本地用户白名单，接入范围由飞书后台管理。若仍显示旧版“未授权”提示，检查实际安装目录是否已更新并重启 Harness。旧配置中的个人权限覆盖继续保留，但不会完成姓名确认。若机器人连姓名提示都不回复，继续检查事件入口、应用可用范围和飞书回复权限。

权限预设仅支持 `read-only` 或 `workspace-write`；旧配置中的 `danger-full-access` 会被拒绝，需在本机改为上述值。远程飞书会话仅开放受限的个人工作区文件、历史、当前消息附件及个人邮箱工具，不开放任意 Shell、通用 MCP 或跨用户飞书 API。因此“执行终端命令”或读取其他人的目录不再属于支持范围。

工作目录现在是用户子目录的根路径。管理员放在根路径中的旧项目不会自动变成每个用户的共享目录，需要将获准使用的文件放到对应用户子目录。不要为恢复旧行为改为完全访问权限。

## `/new` 后旧任务为什么还在运行？

`/new` 不取消正在执行的任务。旧任务完成后才归档旧会话，后续消息使用新上下文，避免同一机器人中的同一用户同时出现多个当前可见会话或修改同一工作区。等待中的补充消息也不是中断命令。可使用 `/status` 检查当前聊天状态，在本机 Harness 查看正在执行的任务。

默认每日 Asia/Macau 凌晨 4 点归档旧会话，无需等待新消息；正在执行的任务结束后再切换，不会强制截断。SQLite 历史、Harness 归档日志和工作文件继续保留，下一条消息才新建会话。跨群聊/私聊切换也会归档上一聊天的会话，历史查询仍按当前聊天隔离。

若升级后仍看到已关闭的旧会话，重启时插件会补归档遗留记录。旧数据库若缺少身份资料，需先收到一条通过验证的飞书消息以自动补齐；此后无人发消息也能定时切换。检查 Harness 是否持续运行，以及所设时区和时间是否正确。

## 历史找不到，或删除之后 Agent 仍记得

- 历史查询只覆盖当前租户、用户和聊天，其他群聊的记录不会返回；显示名称不是身份依据。
- 旧版逐消息会话不会自动导入新 SQLite 历史库。确认记录是否来自升级前，或已被软删除。
- 每日切换和 `/new` 不删除历史；可以明确要求 Agent 按日期和关键词查找以前的内容。
- 历史工具的修改和软删除不修改 Harness 原始日志、飞书消息、备份或已加载的模型上下文。需要刷新当前上下文时发送 `/new`；这不代表已经从其他存储彻底擦除。
- 数据库是本机持久存储，不能代替可靠消息队列。重启后如缺少最终答复，先查看 Harness 任务结果，避免重复执行有副作用的操作。

## 图片、文件、视频或音频无法接收/发送

先完成姓名确认；确认前不下载附件，只继续姓名确认。确认后请重新发送。接收消息仍只需订阅 `im.message.receive_v1`，但资源下载、图片/文件上传及回复消息各有 API 权限要求；按 [附件权限](setup.md#附件权限) 检查并完成应用发布。接收事件权限不代表已经具有资源下载权限。

- 接收每条最多 10 个资源、合计 100 MiB；发送图片最多 10 MiB，文件/视频/音频最多 30 MiB。超限时缩小或拆分文件再发。
- 视频消息只支持 MP4，音频消息只支持 OPUS；其他格式请要求用 `kind=file` 发送。插件不负责转码。
- `feishu_send_file` 使用自己的工作目录内相对路径。普通文本回复中的本地路径不会自动上传；要让 Agent 实际调用发送工具。
- 发送只在当前已领取的飞书消息任务中生效，没有收件人参数；空闲 Harness 会话、其他人的目录或已丢失的文件不能直接发送。
- 检查个人 `incoming/...` 文件与历史中的原名、接收时间、相对路径。`/new` 和每日切换保留文件；若磁盘文件被手动删除，历史记录不能代替备份恢复内容。
- 图片存储还受 Harness 图片格式与尺寸限制；文件资源被飞书撤回、过期或限制下载时，以 API 错误提示为准。不要把用户发来的图片误作机器人自己上传的图片下载，两者 API 不同。

## 已收到图片或视频，为什么模型说不能看？

收发媒体与理解内容是两回事。当前模型必须明确声明支持图片输入，才能使用图片内容及 `feishu_read_image` 读取历史图片；纯文本模型只保存文件，并不会看图。请在 Harness 选择已有的支持图片模型后重试，插件不会替你安装或配置新模型。

视频和音频目前按文件保存和转发，不自动分析画面、转写语音或提取字幕。插件也没有 OCR、通用 PDF/Office 解析或格式转码。可上传可读的 TXT/Markdown/CSV，或自行先转换所需内容。工作区写入权限允许用 `workspace_write` 生成这些文本文件，再通过 `feishu_send_file` 发回；仍不开放任意 Shell。

## 长连接显示「等待配置」「正在重连」或「连接异常」

- **等待配置**：先填写 App ID / App Secret 并保存。
- **正在连接 / 正在重连**：确认 Harness 所在机器可以访问飞书服务，保持进程运行，再刷新连接状态。
- **连接异常**：检查页面状态信息、应用凭据及 Harness 日志；凭据修改后需要保存才能更新运行连接。
- **已连接但没有会话**：继续检查飞书后台是否选择长连接、是否订阅接收消息事件、权限及应用版本是否生效。已连接本身不证明事件已送达。

页面定期刷新状态，也可手动点击 **刷新连接状态**。Webhook 与长连接切换时，插件会更新对应连接，无需靠反复重启来保存下拉选择。

## 为什么设置页显示「ngrok 未运行」？

只有选择 ngrok 接入方式时，设置页才检测本机 `127.0.0.1:4040` 上指向**当前 Harness 端口**的 HTTPS 隧道。以下情况都可能导致检测不到：

- ngrok 没有启动，或已退出。
- 本机 ngrok 检查接口不在默认 `4040` 端口。
- 隧道转发到另一个端口、另一台机器，或没有 HTTPS 公网地址。
- 使用的是其他反向代理服务。

已有可用公网入口时，可以选择 Cloudflare Tunnel 或自定义公网地址并填写「公网服务地址」，无需依赖 ngrok 自动检测。这两种方式不使用 ngrok 检测结果，也不在地址留空时回退 ngrok。仅填写地址不代表进程已运行；可使用插件启动/守护功能，或继续在外部终端管理。自定义公网接入不支持插件启动。

## Cloudflare 地址已配置，为什么飞书仍然无法访问？

「地址已配置，连接未验证」只说明你填写了 HTTPS 地址，插件不会将此状态当作连通成功。依次检查：

1. 已安装 `cloudflared`，隧道进程仍在运行，且目标为当前 Harness 端口。
2. Quick Tunnel 是否已重启。每次启动可能获得不同的 `trycloudflare.com` 地址，旧地址需同时在插件与飞书后台替换。
3. 飞书后台使用完整 `https://your-domain.example/webhook/feishu`，插件填写根地址。
4. 使用命名隧道时，检查 DNS、隧道凭据与 `ingress` 的本地服务地址；`--name` 不与 `--port` 同时使用。
5. Cloudflare Access 或其他代理策略是否要求飞书完成浏览器登录。回调请求必须能直接到达处理接口。

如果 Quick Tunnel 在启动阶段失败，也检查 `.cloudflared` 目录中是否已有 `config.yaml`；Cloudflare 官方说明该配置可能与 Quick Tunnel 冲突。先确认是否应使用已有命名隧道，再按 [Quick Tunnels 文档](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/) 排查配置。

查看启动终端或 `.runtime/cloudflared.log`。后台启动命令返回不代表 Cloudflare 已建立连接；最后仍需完成飞书地址验证和真实消息测试。

## Agent 工作时没有敲键盘表情，或结束后表情残留

插件在接受有效消息任务后主动添加 `Typing` 表情回应，不是飞书客户端的输入框「正在输入」提示。请检查：

- 已更新到包含工作状态功能的版本（0.1.3 或更高）并重启加载新代码。
- 已开通应用身份权限 `im:message.reactions:write_only`（发送、删除消息表情回复），并完成新版本发布或权限生效流程。无需订阅用户 reaction 事件。
- Harness 是否确实创建了飞书任务；被忽略或仍处于姓名确认阶段的消息不会显示该状态。任务很快结束时表情可能来不及被观察。
- 日志中是否有添加/删除表情的权限、认证或网络错误。表情更新失败不会阻止正常任务执行和文本回复。

完成、失败、取消或插件卸载时，插件尝试只清除自己记录的表情；进程强杀、机器断网或远端 API 错误可能留下表情，不能仅凭残留表情认定任务仍在执行。先查看 Harness 会话状态。

## 后台启动命令结束了，页面却打不开

`--background` 只检查进程创建后短时间内是否退出，不是服务就绪检查。查看插件目录下的 `.runtime/harness.log`、`.runtime/ngrok.log` 或 `.runtime/cloudflared.log`，确认实际监听地址或隧道启动结果。

如果日志提示端口被占用，先在原启动终端停止旧实例，再启动新实例；也可以通过 `npm run start:harness -- --port 3081` 选择其他端口，并同步修改隧道端口。启动脚本不会自动终止已有 Harness 服务。

默认前台运行时，日志直接输出到启动终端。分享日志前移除 App Secret、Token、Encrypt Key、带登录令牌的 URL、真实消息正文和不希望公开的工作目录信息。

## 配置了其他事件或卡片回调，为什么没动作？

当前通过 `im.message.receive_v1` 处理文本、图文与支持的附件。机器人入群/出群、已读/撤回、用户表情回应事件、云文档评论、会议/纪要/妙记等事件未实现处理，`card.action.trigger` 卡片按钮回调也未实现。无需为现有聊天和附件收发配置这些项目。

历史记录虽然保存在 SQLite，但没有持久消息队列或重启补发保证。处理中重启、网络失败或进程退出后，先查看 Harness 会话中的结果，避免在不确定任务是否执行的情况下反复重发有副作用的请求。

## 邮箱未绑定、授权失败或邮件没有到达

普通聊天不会强制配置邮箱。先完成姓名确认，再在机器人私聊提出发送请求，或发送 `/mail`。输入本人邮箱后，已知服务商的 SMTP 参数自动匹配，再询问授权码；仅未知服务商或企业域名需要手动提供服务器参数。群聊不能办理个人邮箱绑定或发送邮件。若正在等待授权码，后续普通文本也会被配置入口接收；想恢复聊天先发送 `/mail cancel`，该命令保留已就绪的绑定。

先用 `/mail status` 检查服务地址；邮箱与 SMTP 服务不匹配也会导致认证失败。使用 `/mail server 主机 端口 tls或starttls` 修改服务，再提交该邮箱服务商生成的授权码；不要使用飞书应用的 App Secret 或邮箱登录密码。认证失败时检查第三方客户端访问是否已启用；网络失败或超时检查 Harness 所在机器能否连接所填主机和端口；证书失败检查主机名及 TLS 模式，不要关闭证书验证。尚未配置服务的旧绑定保留邮箱，先自动匹配，无法识别才提示补充参数，无需重填邮箱。插件不支持 OAuth 登录或 IMAP 收信。配置验证不会发测试邮件。因当前明确发送请求进入配置时，验证成功后继续该请求，已明确的收件人无需重填；缺少收件人、主题或正文时只补问缺项。手动 `/mail` 且没有发送任务时不会自动发信。取消或重置会丢弃待续任务，不会从历史中恢复旧草稿。更换授权码可重新配置，删除自己的旧绑定使用 `/mail reset`。

发件人与收件人来自当前用户的绑定，Agent 不能通过工具参数改成其他账号。要修改收件人，在私聊使用 `/mail to 新邮箱地址`。同名用户、不同机器人和不同租户的绑定分别保存，不能依赖另一处已配置的账号。

附件只能来自自己的工作目录，最多 10 个；文本上限 1 MiB，估算 MIME 总体积上限 10 MiB。附件编码会增加体积，因此原文件小于 10 MiB 也可能超限。SMTP 接受只代表服务器受理，不保证送达或进入收件箱；检查地址、垃圾邮件和邮箱服务记录。出现结果不确定的失败时，插件不会自动重发，持久去重也可能阻止同一消息同内容再发；先核实是否已发出，再决定是否发起新的明确请求。

授权码在进入 Webhook 投递、历史和模型前脱敏，保存于 Harness credentials；插件不会删除飞书平台上的原始聊天记录。反馈问题请只提供脱敏状态，不要附带授权码、凭据文件或含秘密的截图。尚未完成真实外部邮件收件的端到端验收，自动测试或 SMTP 登录验证不代表实际投递成功。详见 [个人邮箱发信](setup.md#个人邮箱发信)。

## 反馈问题时提供什么？

可在 [GitHub Issues](https://github.com/icanotcode/dsh-feishu-bot/issues) 提交：插件版本或提交号、Harness 版本、Node.js 版本、操作系统、接收方式、最短复现步骤，以及脱敏后的错误文本或 HTTP 状态。注明问题停在「地址验证」「没有创建会话」还是「会话完成但没有回复」，便于定位。

不要上传应用密钥、完整 Harness 配置目录、带登录令牌的启动 URL 或原始飞书业务消息。

## 飞书能回复，但 Archive 后 Harness 中找不到当前会话

Harness 的 Archive 会隐藏会话，原任务可能仍在运行。当前插件会在收到下一条普通消息时检查归档状态，等旧任务结束后创建可见的新会话；旧会话仍保持归档，历史不会删除。发送 `/status` 可查看归档提示。若仍持续使用隐藏会话，确认插件已更新并重启 Harness。

## 删除飞书 workspace 后如何继续

如果在 Harness 界面删除 workspace，目录和会话日志并未删除。下一条普通飞书消息会恢复工作区注册，并继续原会话，运行中和重启后均适用。此操作不会取消归档其他旧会话。若是直接删除磁盘上的 `.feishu-users/<身份哈希>/` 目录，插件只能重建空目录，原工作文件需要从自己的备份恢复；单独存放的历史数据库仍保留。

## 守护开启了，为什么还不能收到飞书消息？

先确认开关已保存。守护跟随 Harness 进程运行，不是操作系统服务；关闭 Harness 后它不会继续守护。手动停止托管隧道会暂停守护，需再次启动，或关闭守护保存后重新开启保存。

“未找到隧道程序”时，安装当前系统的原生 ngrok/cloudflared 并确认 Harness 的 PATH，或在面板填写绝对程序路径。Windows 使用 `.exe`；不能把 Bash alias、完整命令或脚本路径当作程序路径。自动重试有退避间隔，不会每次刷新页面都重启。

ngrok 的 `4040` API 无响应或已有其他端口/域名的隧道时，插件不会盲目再开进程。确认现有进程的端口、域名和 Traffic Policy。策略文件读取失败不会降级成无策略启动，文件内容也不会被插件修改。

Cloudflare 固定模式需要本地管理的命名隧道 YAML 和 `credentials-file`，以及与公网根地址 hostname 匹配、指向本机 HTTP 服务的 ingress 规则；不接受仅有 Dashboard token 的远程管理配置。临时隧道重启后地址可能变化，必须把新 Webhook URL 填回飞书后台。

状态中的“进程已启动”不等于公网连接成功，连接成功也不证明飞书权限、签名或回调地址配置正确。启动失败详情只给出脱敏提示；必要时在本机终端使用自己的配置检查提供商错误，勿公开凭据或原始日志。
