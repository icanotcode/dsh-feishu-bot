# 推荐的全局 Agent 规则（AGENTS.md 配套片段）

> 以下为与能力桥配套的全局规则示例，放入 Harness 全局指令
> （`~/.dsh/AGENTS.md`）后对所有会话生效。按团队需要裁剪。

```markdown
# 全局路由规则

## 飞书会话入口（薄代理）

飞书隔离会话没有 skill 工具、没有 bash、文件只能读写自己工作区——
「加载 skill」对它们不可执行。飞书侧路由由两层承载：

1. 插件注入：每条飞书消息自动携带插件指引（如邮件流程）
   和按用户角色过滤的能力清单（feishu_capability 机制）；
2. 路由原则：插件自有功能走插件指引；能力类意图走
   feishu_capability（list/load/run）；其余正常对话。

在飞书会话中不要尝试调用 skill 工具或读取用户级技能目录——不在沙箱内。

## 能力发现（技能列表）

当用户发送「技能列表」「你会什么」「有什么功能」「帮助」等询问能力的消息时：

1. Web 会话：基于当前会话技能目录逐项列出技能名称、一句话介绍、
   一个可直接照说的示例说法；不虚构目录外的技能。
   飞书会话：列出内置工具能力 + feishu_capability list 返回的已授予能力。
2. 末尾提示：不需要记命令，直接说需求即可。
3. 同一会话只在首次询问时完整列出一次。

## 新能力接入协议（每次新增/修改 skill 后必须执行）

"装进技能目录"不等于"接入完成"。必须按清单逐项接线并验证：

1. 入口清单：列出系统所有入口，逐个确认新能力从该入口可达。
2. 飞书可达性自查：按开放决策树显式写出 feishu.json（见
   docs/capability-bridge.md），不许依赖默认派生碰运气。
3. 入口级验收：每个入口各发一条真实触发消息验证。
4. 能力发现同步：确认「技能列表」输出能覆盖新能力。
5. 双副本同步：开发版与运行版保持一致。

完成以上五项，才允许宣布"系统建成"。
```
